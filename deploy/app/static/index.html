Procurement audit planner

Agents read West Berkshire Council's purchasing rules, analyse every published payment over £500, fold in past audit opinions and rate the risks. An auditor approves the risks, then an agent team writes and checks the audit plan for sign-off.

A full run takes about 20 to 40 minutes of agent work and about $4 of API credit.

    What runs where

    Each stage is a Claude Code session started by this server through the Claude Agent SDK, in a fresh copy of the project. The sessions load the project's own CLAUDE.md, the skills in .claude/skills and the agents in .claude/agents, the same files used to build the system in VS Code.

    The stages

    A1 runs the extract-rules skill on the Contract Rules PDF and checks every quote against the page it came from. A2 runs the spend-analyst and the findings-analyst in parallel: Python computes every indicator from three months of spend, and the committee papers give past audit opinions and the council's own risk scale. A3 is the risk-assessor, which follows the risk-assessment skill; a builder script drops any rating it cannot trace.

    A4 is the first human gate: you approve, amend or reject each risk. A5 revises the register to match. A6 is the agent team: the planner writes the plan through the audit-program skill, the challenger questions it, and the QA reviewer runs four check scripts. They message each other directly. A7 is your sign-off, allowed only when QA says ready.

    Rules it keeps

    The model reads and judges; Python computes every number. Quotes are checked against the PDFs. Results are indicators to investigate, never findings of wrongdoing. Missing input means stop and report.

    Limits

    Starting a run, recording decisions and signing off need the team passcode, and there is a daily cap on runs. The reference run is the build from Part A of the assignment and is read-only.
